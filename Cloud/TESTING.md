# UPasswords v7 验收测试文档

本文件供人工验收使用,按顺序执行;每节标注前置条件。全部通过的判定
标准是每一节的「预期」都成立。发现问题请记下节号 + 现象(日志在
`~/Library/Application Support/UPasswords/` 下按级别过滤,敏感内容不落日志)。

> **前置说明**:云端已部署上线(api.upasswords.com /v2,2026-10-18),
> A–H 全部小节均可直接执行。C 节起会触发真实验证码邮件(发往你的邮箱)。

---

## A. 本地基础(离线,无需网络)

**A1 创建库与解锁**
1. 全新启动 macOS App(或 iOS 模拟器)→ 引导页 → 创建库:命名 `Main`、设置主密码。
2. 退出 App 重开 → 输主密码解锁。

预期:创建后直接进入主界面;重开后锁屏解锁成功;错误密码被拒(提示密码错误)。

**A2 条目 CRUD 与回收站**
1. 新建条目:选「登录」模板 → 填标题 `GitHub`、用户名、密码、网址 `github.com` → 保存。
2. 编辑该条目改密码 → 保存;再建一个标签 `工作`,拖拽条目打标签。
3. 删除 `GitHub` 条目 → 进回收站 → 可恢复;再从回收站彻底删除。

预期:列表/详情/标签即时刷新;回收站恢复后字段完整;彻底删除后条目
**从库里完全消失**(v7 无墓碑——本地文件里不留任何标记)。

**A3 附件**
1. 编辑条目 → 添加一张图片附件与一个文本文件附件 → 保存。
2. 重启 App 解锁 → 打开该条目查看附件。

预期:附件内容与大小一致,可正常预览/打开。

**A4 泄漏检测(异步无感知)**
1. 新建条目,密码填 `123456`(已知泄漏密码);另一条密码填随机强密码。
2. 打开安全页 → 手动「检查泄露密码」。

预期:检查过程后台运行、无卡顿;`123456` 条目被标记「已泄漏」并出现
红标;强密码条目干净。断网时检查静默失败(不误报干净),联网后恢复。

**A5 改密(本地)**
1. 设置 → 修改主密码(旧 → 新)→ 用新密码解锁 → 数据完整。
2. 用旧密码尝试解锁 → 拒绝。

预期:改密后旧密文作废,新密码解锁数据无缺;回收站/附件/标签均完整。

## B. 多端数据格式一致性(本地对拷,无需云端)

**B1 文件对恢复**
1. macOS 上把 `~/Library/Application Support/UPasswords/Databases/Main.upw`
   与 `Main.upwkey` 拷到 iOS 模拟器(或另一台 Mac)。
2. 引导页选「从文件恢复」→ 选这对文件 → 输主密码。

预期:条目/标签/附件/图标全部一致恢复。

## C. 账户与绑定(需部署)

**C1 注册/登录**
1. macOS 设置 → 云同步 → 输邮箱 → 收验证码 → 登录(首次自动注册)。
2. iOS 同邮箱登录。

预期:两台设备都登录成功;设置页登录后立即翻到已登录视图(无需重启 App);
「管理设备」能看到两台设备,本机一行带「本机」徽标(同名设备也可区分),
重复登录同一设备不会堆积多条会话(旧会话自动撤销)。

**C2 绑定即全量上行**
1. macOS 先建若干条目 → 登录并启用云同步。

预期:登录成功后一轮自动同步把全部条目推上云端(设置页「上次同步」
时间刷新;服务端 `vaults.item_count` = 本地条目+标签数,可让开发者查)。

## D. 行级同步主链路(需部署;两台设备)

**D1 编辑后跨端收敛**
1. macOS 修改 `GitHub` 条目的密码 → 保存。
2. 等 ≤60 秒(或 iOS 进前台)→ 打开 iOS 查看。

预期:iOS 在一分钟内收敛到新密码(行级增量,非整库);反向 iOS 改 →
macOS 同样收敛。

**D2 离线编辑与补传**
1. iOS 开飞行模式 → 新建条目 `Offline` → 退出飞行模式。

预期:联网后自动同步,`Offline` 出现在 macOS;离线期间一切本地功能正常。

**D3 删除收敛(无墓碑)**
1. macOS 彻底删除 `Offline` 条目。
2. iOS 等待一轮同步(或进前台)。

预期:iOS 上该条目消失且**不会复活**(包括 iOS 曾离线持有旧副本的场景:
其迟到推送撞 not_found 被丢弃)。

**D4 同条目并发冲突**
1. 两端断网;两端各自修改同一条目的不同字段;两端先后恢复网络。

预期:后同步的一端按 mtime 决胜收敛到同一内容,无弹窗、无数据重复。

**D5 新设备恢复**
1. 新装 App(iOS 模拟器抹掉重装)→ 登录同账户 → 恢复页列出 `Main` →
   输主密码恢复。

预期:条目/标签/附件完整恢复并直接进入主界面;此后编辑正常双向同步。

**D6 改密传播(rekey)**
1. macOS 修改主密码。
2. iOS 等待下一轮同步(或手动同步)。

预期:iOS 被强制锁定并提示「密码已在其他设备修改」;输入新密码后
全量对齐,数据完整;旧密码不可再解锁。

## E. 附件云同步(需部署)

1. macOS 条目添加图片附件 → 同步;iOS 打开该条目。

预期:附件跨端可见可开(行内携带;超限附件走 R2 通道自动上传/懒拉)。

## F. 网站目录(需部署 + 目录导入)

1. 管理面导入目录(含 github.com 中英文名与图标)。
2. 新建条目输入网址 `https://github.com`。

预期:名称自动填 `GitHub`(中文环境有中文名则用中文),图标自动带出;
未收录网址回退现行行为(抓 favicon / host 作名称)。

## G. 泄漏检测云端代理(需部署)

1. 断开 HIBP 直连路径的模拟:正常网络下安全页手动检查。

预期:检查经 `api.upasswords.com` 代理完成(抓包只见自有域名请求,
不见 api.pwnedpasswords.com);结果与 A4 一致。

## H. 会话与账户安全(需部署)

1. 「管理设备」撤销 iOS 会话 → iOS 触发任意同步。
2. 注销账户(sensitive 验证码)→ 重新登录同邮箱。

预期:被撤销设备下次同步收到 401,自动退出登录并提示重新登录(设置页
回到登录表单);登出/重登也会即时刷新界面。注销后云端数据清空,重新登录
为全新账户(库里为空)。
